# B2B 어드민 재설계 — 배너 스케줄 관리

> 진행 중인 케이스스터디 원본 기록. 여기서 먼저 배경/문제 → 과정 → 결과를 정리하고, 나중에 `/projects/[slug]` 페이지 콘텐츠로 옮긴다.
> **주의**: 실제 재직 중인 회사의 화면이 아니라, 그 경험에서 얻은 문제의식을 바탕으로 처음부터 새로 설계하는 개인 프로젝트다. 회사 내부 화면·데이터는 포함하지 않는다.

## 배경 / 문제

**페르소나**: 홈쇼핑 MD(운영자) — 하루에도 여러 개의 프로모션 배너를 스케줄에 맞춰 등록·교체해야 함

**문제 3가지**:
1. 배너가 여러 개 겹쳐 있을 때 지금 뭐가 노출 중이고 뭐가 대기 중인지 한눈에 안 보임
2. 순서를 바꾸는 방법이 직관적이지 않음
3. 배너 이미지가 아직 없는 상태(빈 상태)일 때 어떻게 보여야 하는지 기준이 없음

## 과정

### 정보구조(IA)

```
배너 스케줄 관리
│
├── 1. 배너 목록 (List View) ── 문제 1, 2 해결
│    ├── 상태별 필터 (전체 / 노출중 / 대기중 / 종료됨)
│    ├── 배너 카드 (썸네일 + 상태 뱃지 + 노출 기간 표시)
│    └── 순서 변경 (드래그앤드랍 + 순번 직접 입력 둘 다 지원)
│
├── 2. 배너 상세/편집 (Detail View)
│    ├── 기본 정보 (이미지, 타이틀, 설명)
│    ├── 노출 조건 (시작일~종료일, 우선순위)
│    ├── 활성/비활성 토글
│    └── 미리보기 (실제 노출 화면 시뮬레이션)
│
├── 3. 빈 상태 (Empty State) ── 문제 3 해결
│    ├── 이미지 없음 → 플레이스홀더 + "이미지 등록" 유도
│    └── 배너 자체가 하나도 없을 때 → 첫 등록 유도 화면
│
└── 4. 권한별 화면 (범위 제외 — 아래 "결정 사항" 참고)
     └── 일반 운영자는 등록만, 발행 승인은 관리자만 가능 (승인 플로우)
```

### 결정 사항
- **4번(권한별 화면)은 범위에서 제외**한다. 핵심 3개 화면(목록/상세/빈상태)을 깊이 있게 완성하는 게, 4개를 얕게 만드는 것보다 포트폴리오에서 더 강하다고 판단. 시간 여유 있으면 "확장 아이디어"로만 짧게 언급.

### 핵심 화면 와이어프레임 스펙

**화면 1 — 배너 목록 (List View)**
- 상단바: 상태 필터 탭(전체/노출중/대기중/종료됨) + 우측 "새 배너 등록" 버튼
- 배너 카드: 드래그 핸들(≡), 썸네일, 타이틀, 상태 뱃지(노출중=초록/대기중=회색·노랑/종료됨=빨강 계열), 노출 기간, 순번(드래그 또는 직접 입력)
- 카드 클릭 → 상세/편집 화면 이동

**화면 2 — 배너 상세/편집 (Detail View)**
- 좌측: 이미지 업로드 + 미리보기
- 우측 폼: 타이틀, 설명, 노출 시작일~종료일(date picker), 우선순위, 활성/비활성 토글
- 하단: 저장/취소 버튼

**저해상도 와이어프레임(구조 확인용)**: [`assets/banner-admin-wireframes.html`](./assets/banner-admin-wireframes.html) — 위 3개 화면 스펙을 그레이스케일 박스로 시각화한 것. 색상/타이포는 최종 디자인 아니고, Figma 작업 전 구조 검토용.
- **에러 상태**: 필수값 누락, 종료일 < 시작일 → 인라인 검증 메시지 (별도 화면 없이 여기서 커버)

**화면 3 — 빈 상태 (Empty State)**
- Case A (배너 0개): 목록 중앙에 일러스트 + "등록된 배너가 없습니다" + "첫 배너 등록하기" CTA
- Case B (이미지 없음): 썸네일 자리에 회색 플레이스홀더 + "이미지를 등록해주세요" + 업로드 버튼
